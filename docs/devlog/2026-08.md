# 16/08

Moved from `std::vector<Body> bodies_` to `std::vector<std::unique_ptr<Body>> bodies_` in `World` as I'll be adding `Constraint` soon. Unlike `Contact`, I think I'll need to actually keep track of the bodies, like 

``` cpp
struct Constraint {
	Body* a;
	Body* b;
	
	// solve, get_inv_m, etc
}
```

That means that just using `std::vector<Body>` wouldn't work, as when it re-allocates on a size change, the pointers for `Constraint` wouldn't work. This isn't SIMD friendly though, but I'll cross that bridge later. Most of this will probably be reworked for the 3D physics engine anyway. 

I also learned about `requires` with templates in C++. Templates are seeming better and better in C++, but I can't help but feeling like they're a bit of a footgun. 

Looks like using a `operator()` is better than `operator[]` for matrices - https://isocpp.org/wiki/faq/operator-overloading#matrix-subscript-op


# 21/08

Pikuma uses inheritance for the different types of constraints. I do feel an aversion to inheritance, maybe it's because of my F# experience? Or because I'm trying to prematurely optimise performance.

But in any case, I only have 2 constraints, contact and distance, and using either inheritance or variants for the data feels a bit premature. I'm going to follow the rule of three, and revisit later when I move to 3D
