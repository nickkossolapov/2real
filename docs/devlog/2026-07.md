# 16/07

Pikuma's circle-polygon algorithm doesn't work for non-rectangular polygon. It just checks if the circle is on the right of one of the lines, and returns the first one it finds. But for obtuse angles, two may actually be to the right of the line, so it may return the first one.

I couldn't (easily) find a circle-polygon collision detection algorithm online, so I came up with my own. It does the following:

1. Find the nearest vertex to the circle.
2. Check the dot product against vertex to the left and right against the vertex to circle line.
3. Return the one with the less-positive projection.

This works both for positive and negative dot products. I should probably write an article and put some diagrams to better explain this. But I'm tired so it can wait.

I have a new strategy that seems to work:

1. Check if the point is inside the polygon
2. Check if the circle intercepts any corners => get contact info
3. Ensure that the circle is within the bounds of the line by check the dot product at both ends 
4. Get the normal distance, and keep track of the one closest to 0, preferring any positive value over a negative one
5. Check that the minimum reported distance is either positive, or negative when inside the polygon => return contact info

![[../attachments/Pasted image 20260716200558.png]]

Still not sure how efficient this algorithm is though.


Bit more thinking, and it turns out the SAT approach was actually the best, but instead of taking the min, take the max. The max will be the best for convex shapes, as the perpendicular distance for any line on the edges at angle will be smaller, either smaller positive or negative.
